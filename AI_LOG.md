# Как использовался ИИ

Работал в Codex (модель семейства GPT-6) с ролями бэкенд-разработчика,
тестировщика и DevOps. PDF изучал через `pypdf`; результат проверял командами
Alembic, Ruff и pytest. Решения и исправления сверял с исходным ТЗ.

Ключевые запросы к ассистенту:

1. Бэкенду: «Реализуй FastAPI API по ТЗ: суммы только в копейках, точный график,
   идемпотентность с уникальным ключом, допустимые переходы статусов и HMAC по
   сырому телу запроса». После уточнения требований: «Отдели HTTP, бизнес-логику
   и SQLAlchemy; PostgreSQL сделай штатной базой».
2. Тестировщику: «Проверь обязательные сценарии и бонусы через pytest + httpx:
   промокод в разном регистре, рассрочку 3/6/12, отсутствие дублей, 409 без
   изменения статуса, 404, подпись и фильтры. Проверяй тело ответа и БД».
3. DevOps: «Добавь воспроизводимый запуск, Docker Compose, миграции, CI с Ruff
   и pytest, правила для ассистента и README с curl-примерами».

Во время ревью нашёл два слабых предложения модели. Сначала она создавала
таблицы через `create_all()` при запуске API: это оставило бы базу без записи
Alembic и мешало последующему `upgrade`. Убрал автосоздание, запуск теперь
начинается с миграции. Также сначала Pydantic валидировал вебхук до проверки
подписи: повреждённый неподписанный JSON мог вернуть 422 вместо требуемого 401.
Порядок изменён: сначала HMAC над сырыми байтами, затем валидация тела.
После правок прошли 20 тестов, Ruff и проверка схемы Alembic; отдельно поднял
PostgreSQL с API через Docker Compose и проверил маршруты и подписанный вебхук.
